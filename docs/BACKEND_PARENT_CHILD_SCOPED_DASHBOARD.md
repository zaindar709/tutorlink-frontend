## 0. Product change (important)

Parents **do not** sign in or sign up.

1. Student generates a code (student app, already authenticated).
2. Parent opens the **web dashboard** and **pastes that code**.
3. Dashboard shows **that studentâ€™s** real sessions / progress / payments.
4. Parent pastes **another childâ€™s code** â†’ that child is added. Switch between children.

**The link code is the only credential.** Do **not** require Firebase parent tokens, `role: parent`, or `/api/auth/register` for this dashboard.

## 1. What the product must do

1. A **student** generates a parent-link code bound to that studentâ€™s Mongo `_id`.
2. Anyone with a valid code can open **that childâ€™s** dashboard (no parent account).

## 3. Non-negotiable rules (do not break the app)

1. **No parent login.** `401` on `?code=` because â€œnot a parent userâ€ will break the dashboard. Authorize by **valid code â†’ studentId** only.
2. **Do not invent demo children.** Return the student who owns that code.
3. **Do not force 0% on link** if that student has completed sessions.
4. **Never mix children.** `?code=` for student A must not include Bâ€™s bookings.
5. **One code, one student.** Code generated by A never returns B.

7. **Used codes must still open the dashboard** on refresh (parent has no account to â€œstay logged inâ€). After first successful view, keep allowing GET by that same code until the student generates a new code or an admin revokes it.

## 6. How to compute **this childâ€™s** stats

Always `Booking.find({ studentId })` for the student that owns the code.

| Field | Formula |
| ----- | ------- |
| `attendanceRate` | `round(100 * completed / max(completed + missed, 1))` |
| `sessionsThisMonth` | completed + upcoming + live this calendar month |
| `avgScore` / `overallProgress` | mean of latest per-subject scores; **0 if none** |
| `subjects` | interests, else distinct booked subjects |
| `grade` / `board` | student profile |
| `weeklyBars` | exactly 5 numbers 0â€“100 |

**No completed sessions:** zeros, empty upcoming, AI: `"{name} has no session history yet."`  
**Has history:** show real bookings even if the parent opened the code today.

## 10. Acceptance checklist

1. Parent web shows **code paste**, not email/password.
2. Valid code → dashboard for **that** `studentId` only.
